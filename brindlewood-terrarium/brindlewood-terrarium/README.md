# Brindlewood Bay — Fish Market Investigation Prototype

> **What this is:** A small, throwaway prototype to test whether AI-driven Maven agents can produce a coherent, consistent, and entertaining investigation scene. This is a learning project — the code should be simple enough to fully understand, and the scope small enough to finish in a few days to a week.

> **What we're testing:** Can three Maven agents maintain distinct personalities, react to clues differently, remember what happened earlier in the scene, and produce fiction that feels like a story rather than disjointed LLM outputs? Does the player's authored context (establishing question, painted scene) ripple through the fiction meaningfully?

> **What we're NOT testing:** Pretty UI, persistence, multiplayer, deployment, language learning, Theorize phase, or any campaign-level features. The UI should be functional and show us what's happening — including behind-the-scenes logs — but doesn't need to look good.

---

## Tech Stack

- **Frontend:** Vite + React + TypeScript
- **Backend:** None for this prototype. LLM calls happen directly from the browser using an API key in a `.env` file. This is local-only — never deploy this version.
- **LLM:** Anthropic Claude API (called from the client via fetch)
- **Data:** Static JSON files for Maven profiles, suspect profiles, location data, and the clue pool. No database.
- **Game state:** React `useState` — lives in memory, resets on page refresh. That's fine.

## The Scene

**Location:** The Fish Market

> *What do you see that reminds you why you love the fish market? Or, what about this place makes you hate coming down here?*

The player will answer this "Paint the Scene" prompt at the start. Their answer becomes a persistent detail that Mavens reference throughout.

**Suspects present:**

- **Etienne Beauregard, a fishmonger** — Silver beard. Hale. Warm. An old friend of the Krauses who agreed to store Albert's body in cold storage as a kindness. *"I'd do anything for the Krauses. Everything I have in this world is because of them. When they told me they needed somewhere cold to store Albert's body, I was more than happy to make room between the cod and the pollock."*

- **Sara Krause, a daughter** — Frumpy. Hand-wringy. Easily cowed. A homemaker with three little ones back in Boston. The only person who seems genuinely upset about Mr. Krause's death. *"Do you really think someone could have murdered my father? It's—it's too horrible to even contemplate!"*

**Mavens present:** Birdie, Pearl, and Doris (all three, moving as a group).

**Mystery context:** Albert Krause, wealthy financier, was dragged out of the bay dead. The family claims he was drunk and fell overboard from their yacht. Sheriff Dalrymple suspects foul play.

**Establishing Question:** *"You met one of the Krause children several years ago. What were the circumstances around that meeting?"* — The player answers this from the perspective of one Maven at game start. This answer must be referenced by the Mavens during investigation.

## Game Loop (Investigation Phase Only)

This prototype runs the investigation loop from the design blueprint, simplified to one location.

### Turn Structure

1. **Player selects a Maven** — Birdie, Pearl, or Doris. Player has full control over who goes next.
2. **Selected Maven proposes 2-3 actions** — Generated by the LLM based on the Maven's personality, the scene context, clues found so far, and their current beliefs. Each proposal includes:
   - What the Maven says (in character voice, 1-2 sentences)
   - The move type: `basic`, `meddling`, `day`, or `cozy`
   - What/who they're targeting
3. **Player picks one action** from the proposals.
4. **Resolution:**
   - **Basic Move:** Auto-succeeds. LLM generates a brief scene (2-4 sentences). No clue, but may surface character interaction or environmental detail.
   - **Meddling Move:** Roll 2d6 + ability modifier.
     - **7-9:** Clue found with complication. Player curates the clue (see below). LLM generates the complication.
     - **10-11:** Clean hit. Player curates the clue. LLM narrates the discovery.
     - **12+:** Clue + Void Clue. Player curates a regular clue. A Void Clue is also automatically surfaced.
     - **6 or below:** Miss. No clue. LLM narrates how it goes wrong.
   - **Day Move:** Roll 2d6 + ability modifier.
     - **10+:** Success. LLM narrates.
     - **7-9:** Partial. LLM describes vulnerability/cost. Player chooses to push through or back down.
     - **6 or below:** Miss. LLM narrates the failure.
   - **Cozy Move:** No roll. Clears one condition on the acting Maven. LLM generates an intimate character moment between two Mavens.
5. **Belief state update** — After resolution, the acting Maven's belief state updates. The LLM generates a short internal thought reflecting how this action changed their thinking. This is visible to the player.
6. **Scene log updates** — A running text log of everything that's happened.
7. **Repeat** — Player picks the next Maven. Cycle continues until the player decides to stop (no formal end condition for this prototype — we're playtesting feel, not completion).

### Clue Curation (When Meddling Succeeds)

This is the player's most creative moment. When a Meddling move results in a clue:

1. The player sees the **remaining clue pool** — a list of clues that haven't been found yet.
2. The player **picks one clue** from the pool.
3. The player **writes a placement context** — a sentence or two describing where/how this clue appears in the current scene. Examples:
   - *"The blood-soaked rug is rolled up behind a crate of mackerel in the back of the cold storage."*
   - *"Pearl notices Sara fidgeting with an expensive diamond earring — but she's only wearing one."*
4. The selected clue is removed from the remaining pool.
5. The clue text + player's placement context are passed to the LLM for narration and become part of the scene history that Mavens reference going forward.

## Maven Profiles

Three Mavens with distinct personalities that should produce noticeably different behavior given the same scene.

### Birdie

- **Style:** Cheerful, colorful scarves, always carrying a tote bag with a romance novel poking out
- **Cozy Activity:** Baking and sharing treats
- **Traits:** Optimistic, trusting, sees the best in people, BUT has sharp intuition that surprises everyone — she notices emotional details others miss
- **Voice:** Warm, chatty, uses endearments ("dear," "sweetie"), tends to tell anecdotes. When she suspects something dark, she gets quiet — which is alarming because she's never quiet.
- **Stats:** Vitality 1, Composure 0, Reason 0, Presence 2, Sensitivity 1
- **Investigative tendency:** Talks to people. Asks gentle questions that disarm suspects. Proposes tea, shared meals, casual conversation that lets things slip.

### Pearl

- **Style:** Sharp-eyed, pressed blazer, reading glasses on a chain, always has a notebook
- **Cozy Activity:** Crossword puzzles and word games
- **Traits:** Paranoid, suspicious of authority, sees conspiracy in coincidence, asks "who benefits?" She's often right but she's also exhausting.
- **Voice:** Clipped, precise, slightly accusatory. Uses legal/procedural language she picked up from mystery novels. Interrupts.
- **Stats:** Vitality 0, Composure 1, Reason 2, Presence 0, Sensitivity 1
- **Investigative tendency:** Searches rooms, examines physical evidence, cross-references details, presses suspects on contradictions. Confrontational.

### Doris

- **Style:** Practical, fleece vest, sturdy shoes, owns a well-trained golden retriever she sometimes brings along
- **Cozy Activity:** Walking and birdwatching
- **Traits:** Methodical, common-sense, grounded. Not flashy but rarely wrong. She focuses on physical evidence, timelines, and logistics. Skeptical of dramatic theories.
- **Voice:** Dry, understated, occasional deadpan humor. Says things like "Well, that's interesting" when she means "that's extremely suspicious." Doesn't waste words.
- **Stats:** Vitality 2, Composure 1, Reason 1, Presence 0, Sensitivity 0
- **Investigative tendency:** Examines the physical scene, asks practical questions about timelines and logistics, notices things that are out of place or don't add up spatially.

## Game State Shape

All game state lives in a single React `useState` object. No persistence — refresh resets everything.

```typescript
interface GameState {
  // Scene setup (set once at start, never changes)
  paintTheScene: string             // player's fish market description
  establishingAnswer: string        // player's answer to the establishing question
  establishingMaven: string         // which Maven the answer is "from"

  // Investigation state
  currentMaven: string | null       // who's acting right now (null = choosing)
  cycleNumber: number
  dayNight: 'day' | 'night'         // always 'day' for this prototype

  // Clue tracking
  discoveredClues: DiscoveredClue[]
  remainingCluePool: Clue[]
  remainingVoidPool: Clue[]

  // Maven states
  mavenBeliefs: Record<string, BeliefState>
  mavenConditions: Record<string, string[]>

  // History
  sceneLog: SceneLogEntry[]         // everything that's happened, in order

  // UI state
  pendingProposals: ActionProposal[] | null
  pendingClueSelection: boolean      // true when waiting for player to curate a clue
  pendingDayMoveChoice: boolean      // true when waiting for push-through/back-down on 7-9
}
```

## The Prompt Architecture (The Hard Part)

The central challenge of this prototype is **context management**. Every time we ask the LLM to generate Maven behavior, we need to provide enough context for consistency without overwhelming the context window or producing contradictions.

### What every Maven prompt needs

Every LLM call for Maven behavior should include:

1. **Maven personality profile** — traits, voice, investigative tendency (from `mavens.json`)
2. **Scene context** — location description + player's Paint the Scene text + which suspects are present + suspect profiles
3. **Establishing question context** — the player's answer and which Maven it belongs to
4. **Full clue history** — every discovered clue with its placement context and who found it
5. **Scene log summary** — what has happened so far this session (condensed — not full narration, just key events)
6. **This Maven's current belief state** — who they suspect, why, what questions they have
7. **All Mavens' conditions** — Tired, Suspicious, etc.
8. **The specific ask** — "propose 2-3 actions" or "narrate this outcome" or "update your beliefs"

### Prompt types needed

The prototype needs these distinct prompt templates:

| Prompt | When | Input | Expected output |
|--------|------|-------|-----------------|
| **Action proposal** | Player selects a Maven | Maven profile + full context | 2-3 action proposals with move types, as JSON |
| **Basic resolution** | Player picks a basic action | Action chosen + full context | 2-4 sentence narration of the scene |
| **Meddling resolution** | Meddling succeeds or fails | Action + dice result + clue (if found) + placement context | Narration of the discovery/failure + complication if 7-9 |
| **Day move resolution** | Day move rolled | Action + dice result | Narration. If 7-9: describe the cost, ask player to choose |
| **Cozy resolution** | Player picks cozy | Which two Mavens, the cozy activity | Intimate character scene, condition cleared |
| **Belief update** | After any resolved action | Maven profile + all context + what just happened | Updated belief state (suspect, reasoning, questions) as JSON |

### Consistency strategy

- The **scene log** is the source of truth. It's an ordered list of what happened and is included in every prompt.
- **Belief states** are regenerated by the LLM after each action, not accumulated through conversation history. The LLM sees the full context fresh each time and produces a new belief snapshot.
- The **player's authored content** (Paint the Scene, establishing answer) is always included near the top of the prompt so it has high salience.
- Maven **personality traits** are phrased as behavioral instructions, not just adjectives: "You are paranoid — you see conspiracy in coincidence, you suspect authority figures, you ask 'who benefits?'"

## UI Layout (Functional, Not Pretty)

The screen should show enough to playtest and debug. Think two-column layout:

**Main panel (left/center):**
- Scene header (location, suspects, cycle)
- Current action: either Maven picker, action proposals, resolution narration, or clue curation — depending on turn phase
- Discovered clues board (collapsible)

**Side panel (right):**
- Maven thought bubbles — one per Maven showing their current belief summary in their voice
- Dev log (collapsible) — shows dice rolls with modifier breakdowns, raw prompt text sent to LLM, raw response text, current game state as JSON

## What "Done" Looks Like

This prototype is done when you can:

1. Start a session by writing a Paint the Scene description and answering the establishing question
2. Pick a Maven, see 2-3 in-character action proposals
3. Pick an action, see a dice roll (in dev log) and narrated outcome (in main view)
4. On a successful Meddling roll, pick a clue from the pool and write placement context
5. See the Maven's belief state update after the action
6. Repeat for several turns and see the Mavens reference earlier events, clues, and the player's authored details
7. Observe that Birdie, Pearl, and Doris genuinely behave differently — different proposals, different reactions to the same clue, different belief trajectories

The primary success criteria is #7 — **do the Mavens feel like distinct characters telling a coherent story together?** Everything else is plumbing to get there.

## Notes for the Developer (Me)

- **This is a learning project.** Understand every file before moving on. If the AI coding agent generates something you don't understand, stop and figure it out.
- **Start with the engine, not the UI.** Get `types.ts`, `dice.ts`, `game-state.ts`, and `prompt-builder.ts` working first. Test them in isolation by calling functions in a scratch file or the browser console.
- **The prompt-builder is the most important file.** The quality of Maven behavior depends almost entirely on how well the prompts are assembled. Spend time here.
- **Log everything.** The DevLog panel exists so you can see exactly what was sent to the LLM and what came back. Use it constantly.
- **Playtest with different establishing answers and scene descriptions.** The whole point is to see if changing player-authored context changes Maven behavior. Try a heartfelt scene description vs. a goofy one. Try different establishing answers. See what ripples.
- **It's okay to scrap this.** This prototype exists to teach you the stack and test the game feel. The keeper code is the engine folder and the data files. The React components will get rebuilt. Don't get precious about it.
